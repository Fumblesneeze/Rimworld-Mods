# DT-POLICY-HEADER / DT-POLICY-ROW: contextual tolerance controls

Owner `fumblesneeze.megamod`, S138. Contracts: contextual Any/numeric gameplay state, explicit
Apply/Cancel, current policy identity, honest unavailable presentation and atomic enforcement.
Native private instance void targets on `Dialog_ManageDrugPolicies` are
`DoColumnLabels(Rect)` and `DoEntryRow(Rect,DrugPolicyEntry,int)`. These are native game methods;
no owned implementation or original-mod layout is patched/copied.

Reserve a measured right-hand column from each incoming native rectangle, preserving the original
rectangle for the owned label/button. The native body continues to calculate its existing widths
from the narrower rectangle. Header coordinates account for its existing 16-unit scrollbar inset;
row coordinates use the actual native scroll view. A current native row button shows Any, the
retained percentage, Needs review, inactive or unavailable. It opens an owned native contextual
window bound to the exact current Game, manager, selected policy and row. The draft changes no
policy before Apply. Apply rechecks that context and effective support, and Cancel discards it.

Before argument changes, admit the actual incoming rectangle-to-CalculateColumnsWidths chain.
Its receiver, rectangle argument and out-local destinations must be unambiguous. Header's native
width adjustment may precede it. Supplied argument addresses/earlier local address escapes and
branches into a partial producer chain must be accounted for; no name/signature-only admission
or exact full-body match suffices. Labels on harmless no-ops still count as branch entries.
The call guard evaluates constant operations as Single and permits only the native header's
single16-unit subtraction from a variable width (plus identity operations). Its bounded output
control-flow pass requires every normally returning path to read all nine calculated columns;
unreachable reads cannot justify narrowing a rectangle. Forward entry into the entire producer
chain remains supported. Executable fixtures cover lost-width cancellation and skipped drawing.
Earlier rectangle-valued local copies are protected as well as argument/address aliases: a
readonly getter is permitted, but a later overwrite or escaped address is unavailable.
The width calculator must preserve its consumed allocation contract; relevant final provider
effects and outer ordering are checked through HarmonyPublication, not speculative foreign calls.

The target-local calculator predicate tracks the supplied Rect and numeric/address aliases through
its permitted Single arithmetic and nine out writes. The outputs remain addiction/joy/schedule36, icon27,
then (width-135) times name0.25/frequency0.3/mood0.15/joy0.15/inventory0.15. Equivalent combined
subtractions, local Rect copies and unique forward branches are supported; unknown calls,
conditional/backward flow, changed output meanings and later alias overwrites are unavailable.
Variable-width operations are limited to the native integer deductions27/108 or combined135,
followed by one native Single multiplication. Constant-only operations evaluate as Single. This
avoids admitting ideal-algebra cancellation such as width+1e30f-1e30f, whose actual result loses
the width. Equivalent incoming variants must also reproduce the actual fixture outputs. Final
comparison tolerances (scale1e-9, constant1e-6) do not authorize arbitrary affine rewrites.
Actual finite calculator input600..1300 and fit must be independently rechecked before every
reservation. This predicate alone neither admits the editor nor enables restrictions.

Use closed typed prefix bindings for the native Rect value: Harmony's generic __args snapshot
does not reliably reflect earlier ref-argument edits (the decision fixture reproduces this).
Capture exact row/rectangle identities after compatible outer prefixes. Draw only after successful
original execution with the same admitted generation and current context. Restore owned GUI
font/color/anchor/enabled changes in a finally block. A skipped/failed native call cannot commit an
edit or leave GUI state behind. The original native rectangle is not persisted or cached across
windows/games; focus belongs to the current contextual draft only.

The first measured layout reserves at least 120 GUI units (or wider translated label/button text)
and keeps at least 600 for native columns. Those bounds are implementation assumptions awaiting
real seven-language/narrow-window validation; unsupported widths keep choices unavailable and
native UI intact instead of activating hidden limits. This does not copy upstream's three fixed
80% column reductions. Sorting, renaming, defaulting, copy and assignment retain native identities;
future S029 presentation calls the same owned controls rather than patching them.

These two candidates belong to the atomic scheduled/direct-joy/social/editor group. Current
persistence CanUseChoices, common effective enablement, available native layout and actual game
context gate every edit and restriction. Every incoming transpiler generation is validated or
returned unchanged; immutable receipts and provider identity revoke removed/changed callbacks.
Only acquired owned slots are rolled back, with bounded unavailable diagnostics. Original-provider
effective-off retains stored settings and row state. Native layout/edit/apply/cancel/save-switch
scenarios and all required languages remain root acceptance obligations.
