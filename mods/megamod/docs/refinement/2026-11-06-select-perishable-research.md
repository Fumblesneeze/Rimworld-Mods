The source category identifiers are Foods, MeatRaw, PlantFoodRaw, PlantMatter, AnimalProductRaw,
Corpses, CorpsesHumanlike, CorpsesAnimal, CorpsesInsect and CorpsesMechanoid. An ancestor match is
enough, so standard modded descendants can qualify. There is no hardcoded item list or blanket

UI details: button28 high,150 wide,4 gap; body shifted36 while constructor grows34. Label is
Deselect when all globally classified definitions are allowed, otherwise Select. For zero candidates
All returns true, yielding an active no-op Deselect label. The loop ignores parent filter, forced-
hidden definitions, text search, current storage limits and current stack presence. It changes
individual type checkboxes, not fresh/rotten special filters or a persistent predicate.

Static risks, **not reproduced runtime failures**:

- Exceptions can bypass the postfix boolean reset; nesting is not represented. A later unrelated
  ThingFilterUI call could inherit stale context. This is why owned context needs guaranteed cleanup.
- A restricted container's action state uses global candidates it cannot accept; raw SetAllow can
  add hidden/impossible type bits even though native parent acceptance still rejects actual items.
- Full definition/stat evaluation repeats on every drawn button. No cache or lifecycle optimization
  exists in the source; this is structural evidence, not measured frame-time impact.
- Constructor size growth and36-pixel body contraction do not establish correct geometry on1.7,
  where native FillTab constructs content from static WinSize. Exact layout remains to verify.
- No transaction, rollback or aggregate notification exists in the source loop. Current native
  SetAllow can invoke callbacks per change and also modify virtual variants.

## Native comparison and composition

Seven successful extracts: ITab_Storage, StorageSettings, ThingFilterUI, ThingFilter, ThingDef,
CompRottable and CompProperties_Rottable. Current native details:

- ITab_Storage resolves direct IStoreSettingsParent, a qualifying Thing comp, zone or consistent
  selected StorageGroup. It obtains current settings and parent settings and checks output-bill
  compatibility before and after filter editing. Hidden special filters are also passed onward.
- ThingFilterUI uses parent bounds, forced-hidden definitions/filters and a separate quick-search
  view. Its Clear all preserves explicitly hidden exceptions; normal Allow all is parent-bounded.
- ThingFilter.Allows(ThingDef) tests allowedDefs membership only. Actual Thing acceptance also
  depends on ranges/special filters, and StorageSettings additionally applies parent acceptance.
  Thus all type checkboxes checked does not mean every rotten/damaged item is accepted.
- SetAllow(ThingDef) changes only when the bit differs, propagates virtualDefs, invokes its change
  callback and invalidates display-root state. SetAllow(category) and SetDisallowAll have broader
  special-filter effects; they are not safe substitutes for this narrow edit.
- StorageSettings constructs its filter with TryNotifyChanged and forwards notifications to its
  owner. Priority setters have their own hauling consequences. No priority write is needed here.
- Native HasComp(Type) checks exact compClass equality. CompProperties_Rottable sets that native
  class, while actual CompRottable ticking depends on temperature and activity. The source classifier
  checks definition capability, not whether a particular stack is currently rotting. Unrelated or
  derived custom rotting components are not automatically recognized by this exact source predicate.

Use direct owned S005 shared policy, S014 linked-workbench recovery, S049 refill and S050 applicability/transaction mechanisms;
do not copy filters per linked member or patch another owned feature. S050's presets intentionally
replace a type list; this helper only adds/removes its qualifying subset. Each is authoritative
when invoked, with no remembered mode reapplying afterward. Candidate scope for a linked group is
the S005 union of intrinsic member capabilities; each destination's actual restrictions remain.
After the final edit, ordinary unlinked bills retain native output-storage handling. Linked-workbench
rows retain any now-unsuitable destination as unresolved and stop new starts until resolved, as
already specified by S014 and S050. No silent fallback or reset of their shared order is introduced.
